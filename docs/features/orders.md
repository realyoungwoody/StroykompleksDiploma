# Заявки

Клиент оформляет заявку без регистрации. Обязательны имя, российский телефон, согласие и хотя бы одна позиция; email, адрес, желаемая дата и комментарий необязательны.

## Создание

`POST /api/v1/orders` выполняет серверный расчёт, нормализует телефон, создаёт случайный номер формата `SC-XXXXXXXXXX`, сохраняет snapshots позиций и начальное событие статуса `new`.

Frontend отправляет стабильный заголовок `Idempotency-Key` для одной попытки формы. Повтор с тем же телом возвращает существующую заявку и HTTP 200. Тот же ключ с другим телом возвращает 409. Ключ не длиннее 64 символов.

## Отслеживание

`POST /api/v1/orders/track` требует номер и тот же телефон. При неверной паре возвращается нейтральный 404 без уточнения, какой параметр ошибочен. Ответ не содержит имени, контактов, адреса, комментария, admin note или внутреннего id.

Ограничение — 30 запросов за 60 секунд на IP в памяти процесса.

## Статусы

- `new` — новая;
- `contacted` — связались;
- `in_progress` — в работе;
- `completed` — завершена;
- `cancelled` — отменена.

Каждое изменение создаёт строку истории. При первом уходе из `new` фиксируется `first_processed_at`, используемый в метриках. Текущий API разрешает переход между любыми значениями из списка и не реализует строгую state machine.

## Демонстрационные данные

Seed создаёт 11 заявок разных статусов. Система явно маркирует их как demo; данные не передаются реальному предприятию.
